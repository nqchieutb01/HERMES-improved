\section{Limitations}
\label{sec:limitations}

\paragraph{Answer format.}
The S-EMBER results and most analysis tables use the timeline prompt, which costs the uncompressed model about 30
mIoU on single-moment grounding relative to the one-line prompt (\cref{tab:prompt}). The gains of \method over the
uncompressed model on our QVHighlights, ActivityNet and Charades-STA subsets (\cref{tab:ladder}) hold only for this
format. Under the one-line prompt we have run only Coverage and random selection on the full Charades-STA and
QVHighlights sets (\cref{tab:main,tab:fullsweep}), and nothing yet on the full ActivityNet set. Under the official
S-EMBER prompt, \method still grounds better ($+5.5$ mIoU with our parser, $+2.1$ with the official one, which cannot
read 73 of its answers), but its accuracy gain is smaller ($+2.9$), comes mostly from BOLT, and the uncompressed
model ran at batch size 4 \vs 8 (\cref{tab:official}). \TODO{S-EMBER without pruning under the one-line prompt; batch-matched comparison.}

\paragraph{Where the prior is measured.}
We measured the video-free prior (\cref{sec:prior}) only in the timeline format. PCD has no effect on one-line
answers (in runs without the answer reserve), which suggests that the prior decides few or none of those times, but
we have not measured no-video answers in that format. \TODO{no-video answers under the one-line and direct-answer
prompts.}

\paragraph{What drives Coverage.}
The equal quota guarantees every timestamp and helps scores that concentrate on a few frames, such as the HERMES
probes ($+5.3$). With attention from the actual question, a global top-$k$ without the quota matched it in both
settings we tested, S-EMBER with the official prompt and a partial QVHighlights run with BOLT frames. Our evidence
that grounding needs anchors in every frame thus comes from selectors that empty frames (the QA pruners and generic
probe scores) and does not rest on the quota itself. \TODO{global top-$k$ without quota under the timeline prompt;
frame coverage of question top-$k$.}

\paragraph{Minimum tokens per frame.}
Equal quotas fail when a frame pair keeps only 2--4 tokens. Using fewer frames avoids this (\cref{sec:frames}), but
our rule of at least about eight tokens per frame pair comes from those same results and needs held-out validation.
The small-budget runs also use the earlier timestamp rule, which left some NExT-GQA questions with no visual tokens,
so part of the collapse may be an accounting effect. \TODO{small-budget runs with the fixed timestamp rule.}

\paragraph{Short, densely sampled videos.}
On Charades-STA uniform frames are less than a second apart, and on NExT-GQA 64 frames already cover a 40\,s video.
There question-driven selection beats random selection only slightly in grounding ($+0.5$ and $+0.7$ mIoU on
Charades-STA, $+0.6$ and $+1.1$ on NExT-GQA at 10\%), but at 10\% on NExT-GQA it keeps the uncompressed accuracy
while random selection loses about four points. The 5\% NExT-GQA results use the earlier timestamp rule and are
being rerun. On these videos PCD does not raise grounded accuracy in either protocol of \cref{tab:nextgqa-open} and
lowers the scored interval in both.

\paragraph{Where PCD hurts.}
PCD can change how time values are written as well as which. On NExT-GQA it lowers TimeLens-8B's timeline grounding
by $-4.4$ mIoU because more replies lack a parsable interval, and under the official prompt Qwen3-VL-8B writes more
times as minutes:seconds, which the official parser scores as missing. Deployment would need a parser that accepts
both forms or a format check on the contrasted reply.

\paragraph{Upper bounds and the front end.}
\method remains well below the gold-window upper bound of TimeLens-8B with PCD ($-11.0$ mIoU, $-9.7$ accuracy), and
for Qwen3-VL-8B it is below the gold window in accuracy ($-5.3$). With BOLT frames, most of the gain over a
low-resolution input comes from frame selection and resolution, which random tokens on the same frames also get. We
do not count the cost of the SigLIP index.

\paragraph{Not a streaming memory.}
We rebuild a causal memory for each question from the preceding frames and prefill it in full, so peak memory and
time-to-first-token match those of the uncompressed model. \method reduces the memory the decoder reads but not the
cost of building it, and PCD decodes a second, prompt-only row at every step. \TODO{cost table; amortisation over
several questions per video; write-once memory re-ranked at question time.}

\paragraph{Scope of the evaluation.}
Both models come from one family (TimeLens-8B is fine-tuned from Qwen3-VL-8B) and read time from text timestamps.
Most diagnostic results use subsets of 475--500 questions, judged by a local model whose sessions differ by up to
about one accuracy point, and some paired differences mix two GPU clusters. All hyperparameters were chosen on the
S-EMBER questions, and we have not yet evaluated a held-out S-EMBER split. \TODO{a second
model family; held-out S-EMBER split.}

\section{Conclusion}
\label{sec:conclusion}

Pruning for QA keeps what is salient, but grounding needs what is everywhere. A video LLM reads time from timestamp
anchors that survive only with their frames, so QA pruners, which empty unremarkable frames, fall below random
selection on grounding. Keeping in each layer the tokens that the actual question attends to preserves the
timeline. With a quarter of the visual tokens this matches the uncompressed model under the standard grounding
prompt on the full Charades-STA and QVHighlights sets, and with a tenth it keeps NExT-GQA accuracy for both a
general and a grounding-tuned model. When the answer lists what was seen before it states the interval, a video-free
prior writes the times wherever the memory is silent. Contrasting each time value with the model's own no-video
prediction removes this prior, so that with a tenth of the tokens \method grounds better than the uncompressed model
answering in the same format, although the contrast can lower the scored grounding when it disturbs the answer
format. The answer format alone changes single-moment grounding by about 30 mIoU and should be reported in every
evaluation of compressed video memories.
