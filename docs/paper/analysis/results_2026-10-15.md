# CoCo: latest experiment results (collected 2026-10-15 ~13:00 +04)

**Method of collection.** I re-scored every number below from the raw outputs (`results.csv`, chunk CSVs, or TimeLens `all.jsonl`) with read-only copies of the existing scorers, unless the row is marked *(log)*. The copies are in `collect.py` in this directory, and every per-run metric, config and paired result is in `collect.json`. The scorers I copied:

- **NExT-GQA**: `hermes_pool/nextgqa/score.py`. This is the official `eval_ground.py` with VideoMind `check_ans` and TimeLens `extract_time`, which is m:ss-aware. Joint runs use `<choice>` / `<answer>`. Per-question vectors are built as in `nextgqa/paired.py`.
- **S-EMBER**: `reports/report_all.py` `load()` with `--mss`, the m:ss-aware parser the paper uses. Unparsed answers get IoU 0.
- **TimeLens-Bench**: `timelens/score.py` `convert()` plus TimeLens `compute_metrics.py`. Only the first pair is scored, times are rounded to 1 s, and a failed parse becomes [dur+10, dur+20]. Runs with the timeline prompt are scored on the text after the last `Time:`. TL-script runs are scored from `all.jsonl` the way `compute_metrics` does it.

**Checks.** Each copied scorer reproduces the numbers already on record:
- NExT-GQA: all 11 runs match the morning table exactly.
- S-EMBER TimeLens-8B: all 5 runs match. The Qwen3 S-EMBER rows also match the draft (35.0 / 39.3 with m:ss, where the official parser leaves 8 answers unparsed).
- TimeLens: all six full-set anchors and all seven subset TL-script runs match their `all.log` to 2 decimals.

**Read-only.** Nothing outside this directory was written. The scorers' writes to the run directories (`nextgqa_eval.json`, `timelens_pred.jsonl`, the `.log` that `compute_metrics` writes) were removed in the copies. I also found no new `.pyc` files next to the imported modules (`eval_ground`, `timelens.utils`, `eval_grounding`).

**Bootstrap.** Paired over questions, 2,000 resamples, numpy `default_rng(0)`, percentile 95% CI. `*` means the CI excludes 0. Values can differ by ±0.1 from the CIs in the pool reports, which use Python `random` with different index conventions.
